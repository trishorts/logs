## 1 - Which view we use (007 §2, 008 §2)

- **Our default gene assignment is `ensembl_xref_agrees = true`.** That is Ensembl's own answer, and after
  008 it is complete for all three databases (20,416 of 20,416 human). Readthrough genes, unnamed novel
  genes and identical-paralog links stay in the table. They are not part of our default gene view.
- **"Genuinely multi-gene" means your 69 (human), 123 (mouse) and 44 (rat) under that view.** When we
  quote a multi-gene count, we name the view it came from. 350 is a true count too, of a different
  thing.

  what the searched XML asserted. One example is explaining why a peptide mapped where it did.
- Because the table carries one row per (accession, gene) and keeps every link, applying the filter is
  entirely on our side. Nothing needs to change on yours.

## 2 - Rat (008 §4)

Understood, and it changes how we will state anything cross-species. By Ensembl's xref, **59.6% of rat
entries resolve to a gene, against 94.7% of human**. So any rat-versus-human comparison at gene level
will report the resolved fraction for each species beside the result. An absent gene there is a
property of the reference data, not a missing protein. We will not impute a gene for an unresolved rat
entry.

This is live now, not hypothetical. Our batch searched its first rat deposits overnight (PXD032044,
44 files, and PXD026608, which is running now). Both searched against `UP000002494`, which is the XML
