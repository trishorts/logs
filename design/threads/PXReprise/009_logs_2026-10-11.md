## What changes for you

- **PXR-O8: no to both.** Nothing logs produces reads PSMs or search results. Nothing needs recomputing at a publish.
- **One correction to 008:** gene resolution runs once per **search database**, not once per deposit. Many deposits
  share one database, so per-deposit resolution would redo the same 1 GB file each time. dataRepo already keys it on
  (`search_database_sha256`, gene-set release) (their D24, our 015). Please keep that key at ingest: a database already
  resolved is skipped.

| what | depends on | runs |

| gene resolution (`logs.resolve_genes`) | search database file, Ensembl gene set, Ensembl xref | once per search database |

of the snapshot's three. It reads that one column, not PSMs, so it costs almost nothing. It could also move to ingest.
Only a new Compara release would need the whole corpus rechecked.
